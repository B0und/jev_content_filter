# Image model comparison

**Decision:** keep NSFWJS MobileNetV2 for image moderation, but load its pinned TensorFlow.js model files after startup instead of shipping the base64-encoded model in the extension bundle. Neither tested Hugging Face classifier is a better replacement on this fixed evaluation set. The deferred adapter returned exactly the same four category scores as the packaged NSFWJS model on all 25 images, while the raw model files total 2,748,406 bytes versus 3,600,073 bytes for the packaged model representation (about 23.7% smaller).

## Corpus and method

The fixed evaluation split has 25 labeled cases: 12 CivitAI records marked `nsfwLevel=X`, six licensed safe-photo controls, six licensed ordinary-illustration controls, and the existing user-reported Trails in the Sky false-positive example. The 12 positives were selected deterministically from the pinned [dataset revision](https://huggingface.co/datasets/wallstoneai/civitai-top-nsfw-images-with-metadata/blob/4580a03472a54768a8d47a87822cab14e6a75996/README.md), by ascending SHA-256 of `jev-image-benchmark-2026-v1 + filename`: `6453.jpeg`, `6041.jpeg`, `4187.jpeg`, `2681.jpeg`, `7.jpeg`, `5964.jpeg`, `2950.jpeg`, `159.jpeg`, `5920.jpeg`, `2825.jpeg`, `2601.jpeg`, `5600.jpeg`. The dataset card declares Apache-2.0 and describes `nsfwLevel` as source metadata; that declaration is not an independent audit of rights to each underlying image. The user-reported example reuses an existing local fixture instead of copying an asset into the benchmark directory; its external provenance/license is unknown. Case-level source pages, authors, licenses, hashes, caveats, and the deterministic split are recorded in [`image-model-fixtures.json`](./image-model-fixtures.json); the executable procedure is [`image-model-benchmark.mjs`](./image-model-benchmark.mjs).

All classifiers used threshold 0.5 on the benchmark's content-match score. For NSFWJS and MobileNetV4, that score is `porn + hentai + sexy`; `drawings` remains a separate category score and is not treated as explicit content. The MobileNetV4 class order is `drawings, hentai, neutral, porn, sexy`, per its pinned [model config](https://huggingface.co/taufiqdp/mobilenetv4_conv_small.e2400_r224_in1k_nsfw_classifier/blob/504317ad62086f357c9c5f70cf983726ff47efdb/config.json). Falconsai is binary (`normal`, `nsfw`) per the pinned [ONNX config](https://huggingface.co/onnx-community/nsfw_image_detection-ONNX/blob/1ceb3c7fe1e9f3f2507e6df577437f23a9149fd5/config.json); its `nsfw` probability is the content score, with no defensible mapping to NSFWJS's four categories.

The run was executed on 2026-10-01 in headless Chromium 151 on Linux x64 / AMD Ryzen 7 7700. NSFWJS used TensorFlow.js 4.22.0 with the browser's `webgl` backend; both Hugging Face candidates used Transformers.js 4.3.0 and ONNX Runtime Web 1.31.0-dev with one WASM thread. The browser profile was fresh. Shared TensorFlow.js/backend initialization and image-fixture loading occurred before model timing. Deferred NSFWJS's load time includes fetching its raw files and loading the model; the MobileNetV4 ONNX file was prepared and served locally, whereas the Falconsai pipeline fetched its model during pipeline creation, so model-load times are not strictly apples-to-apples. Per-image timings include each runner's prediction path. Exact per-case outputs, raw scores, errors, revisions, and environment details are in [`image-model-results.json`](./image-model-results.json).

The MobileNetV4 configuration declares five output classes and Apache-2.0; its official config specifies a float32 NCHW input tensor of `[3,224,224]` (no batch dimension), bicubic resize, center crop, ImageNet mean/std, and the label order above. The runner softmaxes its five logits. Preprocessing follows the documented `timm` data-config / transform path ([model card](https://huggingface.co/taufiqdp/mobilenetv4_conv_small.e2400_r224_in1k_nsfw_classifier/blob/504317ad62086f357c9c5f70cf983726ff47efdb/README.md), [pinned config](https://huggingface.co/taufiqdp/mobilenetv4_conv_small.e2400_r224_in1k_nsfw_classifier/blob/504317ad62086f357c9c5f70cf983726ff47efdb/config.json), [`timm` inference quickstart](https://huggingface.co/docs/timm/en/quickstart)). It was much faster per image but missed eight positives and produced four false positives at the fixed threshold.

The Falconsai ONNX conversion is a ViT-based binary detector. Its pinned [config](https://huggingface.co/onnx-community/nsfw_image_detection-ONNX/blob/1ceb3c7fe1e9f3f2507e6df577437f23a9149fd5/config.json) specifies three-channel 224×224 images and `normal`/`nsfw` outputs; the benchmark used Transformers.js's pinned image-classification processor (RGB, scale by 1/255, normalize by mean/std `[0.5, 0.5, 0.5]`) and q4 ONNX weights. Its pinned [conversion card](https://huggingface.co/onnx-community/nsfw_image_detection-ONNX/blob/1ceb3c7fe1e9f3f2507e6df577437f23a9149fd5/README.md) identifies `Falconsai/nsfw_image_detection` as the base model; the source [model card](https://huggingface.co/Falconsai/nsfw_image_detection) declares Apache-2.0 and describes a proprietary 80,000-image training set. The conversion card at the pinned revision does not state a license. Although it classified this split correctly, it was about 20.6× the deferred NSFWJS artifact size, loaded in 8.7 seconds, and took about 1 second per image. Its binary output cannot replace the extension's separate `porn`, `hentai`, `sexy`, and `drawings` scores. Transformers.js supports browser inference through ONNX Runtime and uses CPU/WASM by default; its docs recommend quantization for constrained browser resources ([Transformers.js docs](https://huggingface.co/docs/transformers.js/en/index)).

## Recommended image runtime

Use `nsfwjs/core` with the model files pinned to NSFWJS commit `d55a54c51f14380670064cc129b2ea51029c5e46`:

- [`model.json`](https://raw.githubusercontent.com/infinitered/nsfwjs/d55a54c51f14380670064cc129b2ea51029c5e46/models/mobilenet_v2/model.json) — 128,945 bytes.
- [`group1-shard1of1`](https://raw.githubusercontent.com/infinitered/nsfwjs/d55a54c51f14380670064cc129b2ea51029c5e46/models/mobilenet_v2/group1-shard1of1) — 2,619,461 bytes.

The pinned [repository model tree](https://github.com/infinitered/nsfwjs/tree/d55a54c51f14380670064cc129b2ea51029c5e46/models/mobilenet_v2) confirms those artifacts and sizes. The NSFWJS [README](https://github.com/infinitered/nsfwjs/blob/d55a54c51f14380670064cc129b2ea51029c5e46/README.md) documents its five categories (`Drawing`, `Hentai`, `Neutral`, `Porn`, `Sexy`), its 224×224 MobileNetV2 model, and hosting raw model files through the `nsfwjs/core` entry point; the repository has an [MIT license](https://raw.githubusercontent.com/infinitered/nsfwjs/d55a54c51f14380670064cc129b2ea51029c5e46/LICENSE). No separate model-weight license is called out in the model directory.

The extension adapter is [`src/inference/image.ts`](../src/inference/image.ts). It downloads the pinned files through the deferred-download/cache helper, creates an in-memory TensorFlow.js LayersModel, and returns four independent NSFWJS scores. It omits `Neutral` because the extension image contract exposes the other four classes. The original page-context Chromium/WebGL harness returned exactly the same four category scores as the bundled baseline on all 25 cases. A separate built-extension smoke exercised the production offscreen document and ES module worker with `createImageBitmap`/`OffscreenCanvas` decoding on the same 25 assets: maximum absolute category-score difference was `2.1606683731079102e-7`, with zero content-match decisions changed at 0.5. This is numerical agreement on this corpus, not a guarantee of identical pixels or backends across browsers. The importable comparison payload is [`image-comparison.json`](image-comparison.json).

These results support a packaging/runtime cutover, not a claim that the model is generally accurate: the evaluation split is small, source-biased, and not a representative safety benchmark. Expand and independently review the corpus before treating these numbers as product-level quality evidence.
