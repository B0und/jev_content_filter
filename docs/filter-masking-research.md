# Filtering without moving the timeline

Research date: 2026-10-08. The target is zero geometry changes caused by Jev when classification completes, a threshold changes, or a user reveals and hides a post.

## Recommended approach

Keep the original article and its children in normal layout. Mask the body with `visibility: hidden`, while explicitly retaining the native author header, avatar, timestamp, caret menu, action bar and Jev icon. The user must still be able to identify the author and open X's native menu for Mute or Not interested. Render the reason and reveal button in an out-of-flow overlay spanning only the body between the header and footer. Reveal changes visibility and overlay state, without replacing text, image URLs, or measured height.

This recommendation follows the browser's specified behavior: hidden boxes still occupy their normal layout, unlike `display: none`. Hidden content cannot receive focus. Descendants can override inherited visibility, which allows selected native controls to remain visible. Mask descendants by default and grant explicit visibility only to retained regions. Check the actual accessibility tree when mixing hidden ancestors and visible controls, rather than assuming the entire article is uniformly hidden. [MDN visibility](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/visibility)

Apply the same rule to every blocked article, including articles below the viewport. Changing policy after a post enters or leaves the viewport would reintroduce different hidden and revealed geometry. This is an implementation inference, rather than an X API guarantee.

Use an opaque neutral surface over image content if a black placeholder is desired. Keep the original image node and sizing rules underneath. Reserve the post's actual occupied space, including native media, quote cards and preview cards. The overlay must not participate in sizing or cover retained controls: absolutely positioned elements leave normal flow. Use an absolutely positioned sibling host; a zero-height sibling alone can still introduce a flex/grid gap, margins, padding or borders. Derive body boundaries from the actual retained header/footer geometry. Avoid adding wrappers that alter native layout, and test parents with gaps, margins and shared cells. [MDN position](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/position), [CSS flexbox specification](https://www.w3.org/TR/css-flexbox-1/)

## Alternatives considered

| Approach                                                   | Decision and reason                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| ---------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Replace text with spaces                                   | Reject. Whitespace may collapse, and replacement changes wrapping. Keeping native text invisible preserves its existing glyph layout. [MDN white-space](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/white-space)                                                                                                                                                                                                                         |
| Swap image URLs for a blank bitmap                         | Avoid. Retain the native node and dimensions; otherwise intrinsic dimensions and loading state require separate handling. Explicit media dimensions reserve space during loading. [Google's layout-shift guidance](https://web.dev/articles/optimize-cls)                                                                                                                                                                                                          |
| `opacity: 0`                                               | Geometry remains, but invisible content can still receive focus and pointer input. It also creates a stacking context. Prefer visibility, or pair opacity with explicit interaction and accessibility handling. [MDN opacity](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/opacity)                                                                                                                                                       |
| Blur                                                       | Keep for the user's existing blur option. Blur still shows recognizable content, so it is unsuitable as the complete hiding mechanism.                                                                                                                                                                                                                                                                                                                             |
| `display: none` plus a measured placeholder                | Avoid. The substitute must reproduce native responsive sizing and late content changes. Reveal can differ from the stored measurement. This failure follows from removing native boxes and substituting their dimensions. [MDN visibility](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/visibility)                                                                                                                                       |
| `content-visibility: hidden` with `contain-intrinsic-size` | Avoid here. Size containment substitutes an intrinsic size; estimates or remembered sizes can differ from current responsive content. It is useful for rendering optimization when the application owns the layout. [MDN content-visibility](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/content-visibility), [MDN contain-intrinsic-size](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/contain-intrinsic-size) |
| Scroll anchoring or manual scroll compensation             | Keep native anchoring intact, but do not use compensation to repair filtering. Anchoring has suppression conditions for geometry and positioning changes; it cannot make resized rows unchanged. [CSS scroll anchoring specification](https://drafts.csswg.org/css-scroll-anchoring-1/)                                                                                                                                                                            |

## Implementation checks

- Keep reveal controls outside the masked body. Do not apply `inert` to the whole article, since that would disable the retained native caret and author controls. If it is used on a body-only subtree, save and restore its original state. It disables focus, clicks and accessibility exposure across that subtree. Restore keyboard focus with `preventScroll` after toggling. [MDN inert](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Global_attributes/inert)
- Use `ResizeObserver` to update overlay bounds, without writing the observed article's size. Resize notifications run before paint, but resizing the observed element can form a loop and produce flashes. Disconnect observers when posts are removed or recycled. [MDN ResizeObserver](https://developer.mozilla.org/en-US/docs/Web/API/ResizeObserver)
- Preserve native media loading attributes and URLs. Visibility masking is visual filtering, not network blocking; lazy images may load when their native geometry reaches the viewport. Do not eagerly load hidden media to obtain measurements. [MDN image loading](https://developer.mozilla.org/en-US/docs/Web/API/HTMLImageElement/loading)
- Test native virtualizer measurements and node reuse. A virtualizer can adjust scroll position when measured item sizes differ; avoid producing those differences or keeping stale masks on recycled nodes. TanStack documents this behavior as general prior art, not evidence that X uses TanStack. [TanStack virtualizer API](https://tanstack.com/virtual/latest/docs/api/virtualizer#shouldadjustscrollpositiononitemsizechange)
- Measure article and following-row rectangles before and after classification, reveal, hide and settings changes. Include posts above, within and below the viewport, long text, media, preview cards and shared cells. Check scroll offsets as well as rectangles. CLS alone is insufficient because it excludes some shifts within 500 ms of user input. [Google's layout-shift guidance](https://web.dev/articles/optimize-cls)
- Exercise retained native controls while the body is masked. Check author navigation, caret opening, Mute/Not interested availability where X provides them, action-bar keyboard focus and menu dismissal. Keep the overlay's hit area within the body so it cannot intercept those controls.

## Prior art and scope

uBlock Origin documents CSS-based cosmetic filtering and domain-specific procedural selection. Its selection approach supports targeting narrow native nodes rather than rewriting content. It does not establish a no-shift guarantee for interactive reveal; Jev needs its own geometry invariant. [uBlock Origin procedural filtering](https://github.com/gorhill/uBlock/wiki/Procedural-cosmetic-filters)

Native X changes can still alter layout: late media dimensions, font replacement, content edits and virtualized row replacement remain under the site's control. Invisible text can reflow when a font loads. The extension should preserve native layout and prove its own transitions add no movement anywhere in the timeline, including below the viewport; it should not promise to freeze every change X itself makes. [Google's layout-shift guidance](https://web.dev/articles/optimize-cls)

X's markup can change or hydrate a post in stages. A body region that cannot yet be separated safely from the native header and controls needs conservative handling and another pass after native DOM changes. Avoid hiding the author/caret or covering a neighboring post just to force a body mask. Record such cases as coverage limits and test later hydration; this is an engineering constraint of DOM-based filtering, not a documented X extension API.

## Verification of this implementation

A native Chromium regression loaded an image after filtering, then revealed the post. The fixed-height placeholder moved the following post by 560px (97px to 657px). Keeping native layout reduced the reveal movement to 0px. Browser tests also verify author/menu/action visibility, flex and grid gaps, responsive wrapping, reveal/hide, shared cells, and below-viewport layout preservation.

In the signed-in headed Chromium profile, a filtered real X post retained its author and caret menu. Reveal measured 0px changes in the post, next cell, height and scroll position; hide again measured 0px height and scroll changes. The native menu opened with ten items. Temporary test settings were restored. Extension contexts had no exceptions; X-owned HTTP403 page exceptions prevent claiming a clean overall live smoke. These measurements describe the observed session, not all future X markup or native layout changes.
